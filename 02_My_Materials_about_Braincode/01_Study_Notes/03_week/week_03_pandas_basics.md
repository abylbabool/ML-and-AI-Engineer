## Данные практики

Два синтетических файла учебного сервиса городских поездок:

- `trips.csv` — заявки на поездки, **одна строка = одна заявка**;
- `zones.json` — справочник зон: код → название и тип.

| Столбец | Смысл | Особенность |
|---|---|---|
| `trip_id` | ID заявки | Ключ. Среднее по нему не считают |
| `requested_at` | Время заявки | При чтении — строка, не дата |
| `zone_id` | Код зоны подачи | Название берётся из JSON |
| `channel` | `app` / `phone` / `web` | Есть неизвестные значения |
| `status` | `completed` / `cancelled` | Отмена — заявка, но не поездка |
| `distance_km` | Километры | Только у завершённых |
| `duration_min` | Минуты | У двух завершённых измерение потеряно |
| `fare_kzt` | Сумма оплаты, ₸ | Только у завершённых. Это не прибыль |

У отменённой заявки нет дистанции, длительности и оплаты. **Пропуск здесь — «не было поездки», а не ноль.**

### 1.1 Подготовка: импорты и пути к файлам

**Что это.** Подключение библиотек и создание рабочей папки, куда кладутся входные файлы и куда позже сохранится отчёт.

**Зачем.** Код анализа должен знать, где лежат файлы. `Path` строит пути одинаково на Windows, macOS и Linux.

**Код — импорты:**

```python
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import json
from pathlib import Path
from tempfile import mkdtemp
from IPython.display import display
```

| Строка | Что происходит |
|---|---|
| `import pandas as pd` | Подключить библиотеку pandas и дать ей короткое имя `pd`. Дальше всё из pandas пишется через `pd.` |
| `import numpy as np` | То же для NumPy (числовые массивы) |
| `import matplotlib.pyplot as plt` | Модуль `pyplot` для графиков из пакета matplotlib |
| `import json` | Модуль для формата JSON |
| `from pathlib import Path` | Взять из модуля `pathlib` один объект — **класс** `Path` (путь к файлу) |
| `from tempfile import mkdtemp` | Взять **функцию** `mkdtemp` — создаёт папку с уникальным именем |
| `from IPython.display import display` | Функция Jupyter для красивого показа таблиц |

> **Python:** `import`, `from`, `as` — ключевые слова самого Python.
> - `import X as Y` — подключить модуль `X` целиком под именем `Y`.
> - `from X import Y` — взять из модуля `X` только объект `Y`, и дальше писать просто `Y`, без `X.`.
>
> Откуда библиотеки: `json`, `pathlib`, `tempfile` — **стандартная библиотека**, идут вместе с Python. `pandas`, `numpy`, `matplotlib` — **сторонние**, ставятся через `pip install`. `IPython` приходит вместе с Jupyter.

**Код — настройки:**

```python
pd.set_option("display.max_columns", 12)
plt.rcParams.update({"figure.figsize": (8, 4), "figure.dpi": 110})
print("pandas:", pd.__version__, "| NumPy:", np.__version__)
```

| Строка | Что происходит |
|---|---|
| `pd.set_option(...)` | Функция pandas: показывать до 12 столбцов, не скрывать их за `...` |
| `plt.rcParams.update({...})` | `rcParams` — атрибут-словарь настроек графиков; `.update()` — метод, который меняет в нём значения: размер 8×4 дюйма, чёткость 110 dpi |
| `print(...)` | Встроенная функция Python. Несколько аргументов через запятую печатаются через пробел |
| `pd.__version__` | Атрибут модуля — строка с версией. Без скобок, потому что это значение, а не действие |

> **Python:**
> - **Функция** вызывается сама: `print(x)`. **Метод** — функция, «принадлежащая» объекту, вызывается через точку: `rcParams.update(...)`. **Атрибут** — значение объекта через точку без скобок: `pd.__version__`.
> - `{"ключ": значение}` — **словарь** (dict): пары ключ → значение.
> - `(8, 4)` — **кортеж** (tuple): упорядоченный набор значений в круглых скобках. Похож на список `[8, 4]`, но его нельзя изменить после создания.

Вывод:

```text
pandas: 2.2.3 | NumPy: 2.1.3
```

**Код — данные внутри ноутбука (сокращено):**

```python
TRIPS_CSV = """trip_id,requested_at,zone_id,channel,status,distance_km,duration_min,fare_kzt
1001,2026-10-05 06:00,Z01,app,cancelled,,,
1002,2026-10-05 06:30,Z03,phone,completed,3.0,12.7,1100
...
"""
ZONES_JSON = r'''[ {"zone_id": "Z01", "zone_name": "Центр", "zone_type": "Смешанная"}, ... ]'''
```

- `TRIPS_CSV = ...` — **переменная**: имя, которое ссылается на значение. Имя КАПСОМ — договорённость «это константа, не меняем».
- `"""..."""` — многострочная строка Python.
- `r'''...'''` — «сырая» строка: обратные слэши `\` не обрабатываются как спецсимволы.
- `,,,` в конце строки отменённой заявки — три пустых поля. При чтении они станут `NaN`.

**Код — папка и файлы:**

```python
RUN_DIR = Path(mkdtemp(prefix="week03_run_", dir=Path.cwd()))
DATA_DIR = RUN_DIR / "data"
OUTPUT_DIR = RUN_DIR / "output"
DATA_DIR.mkdir()
OUTPUT_DIR.mkdir()
```

| Строка | Что происходит |
|---|---|
| `Path.cwd()` | Метод класса `Path`: текущая рабочая папка (где открыт ноутбук) |
| `mkdtemp(prefix=..., dir=...)` | Создаёт новую папку с уникальным именем `week03_run_xxxx` и возвращает путь **строкой** |
| `Path(...)` | Превращает строку в объект `Path` |
| `RUN_DIR / "data"` | Оператор `/` склеивает части пути → `.../week03_run_xxxx/data` |
| `.mkdir()` | Метод: создать папку на диске |

`prefix=` и `dir=` — **именованные аргументы**: значение передаётся по имени параметра, порядок не важен.

> **Python: `Path` и оператор `/`.** Для чисел `/` — деление. Но класс `Path` переопределяет этот оператор: `Path / "строка"` означает «добавить часть пути». Разделитель (`/` или `\`) подставится под вашу ОС сам. Работает, только если хотя бы слева или справа стоит объект `Path`:
>
> ```python
> Path("reports") / "2026-11" / "transactions.csv"   # OK → reports/2026-11/transactions.csv
> "reports" / "2026-11"                              # TypeError: две строки делить нельзя
> ```

```python
(DATA_DIR / "trips.csv").write_text(TRIPS_CSV, encoding="utf-8")
(DATA_DIR / "zones.json").write_text(ZONES_JSON, encoding="utf-8")
print("Готовы trips.csv и zones.json.")
print("Рабочая папка:", RUN_DIR.name)
```

- `(DATA_DIR / "trips.csv")` — путь к будущему файлу. **Скобки обязательны**: точка выполняется раньше `/`.
- `.write_text(текст, encoding="utf-8")` — метод `Path`: записать строку в файл. `utf-8` нужен для кириллицы.
- `RUN_DIR.name` — атрибут `Path`: только последняя часть пути, без папок выше.

Вывод:

```text
Готовы trips.csv и zones.json.
Рабочая папка: week03_run_2yvjnivn
```

**Что вернётся.** `Path(...)` и `RUN_DIR / "data"` → объект `Path` (в Linux/macOS печатается как `PosixPath('...')`). `mkdtemp` → строка. `mkdir()` и `write_text()` меняют диск.

**Типичные ошибки:**

1. `DATA_DIR / "trips.csv".write_text(...)` без скобок → `AttributeError: 'str' object has no attribute 'write_text'`: метод вызвался у строки.
2. Склеивать пути строками: `"data" + "/" + "trips.csv"`. Работает до первого запуска на другой ОС или до лишнего слэша. Используйте `Path` и `/`.
3. Повторный `mkdir()` для существующей папки → `FileExistsError`. Если папка может уже быть: `mkdir(exist_ok=True)`.

### 1.4 Дубликаты: duplicated и drop_duplicates

**Что это.** `duplicated()` помечает строки-повторы, `drop_duplicates()` возвращает таблицу без них.

**Зачем.** Повтор при выгрузке завышает число заявок и суммы. Но удалять можно только **точные** копии. Если ID один, а поля разные, — это вопрос к источнику данных.

**Код — найти повторы:**

```python
print("Лишних полных повторов:", raw_trips.duplicated().sum())
raw_trips.loc[raw_trips.duplicated(keep=False)].sort_values("trip_id")
```

| Часть | Что делает |
|---|---|
| `raw_trips.duplicated()` | Метод DataFrame. Сравнивает строки **по всем столбцам**, возвращает `Series` из `True`/`False` |
| `.sum()` | Число `True` = число **лишних** копий |
| `duplicated(keep=False)` | Помечает `True` **все** экземпляры повторов, включая первый |
| `raw_trips.loc[маска]` | Оставить строки, где маска `True` |
| `.sort_values("trip_id")` | Поставить копии рядом, чтобы сравнить глазами |

Параметр `keep` решает, какую копию **не** считать повтором:

| `keep=` | Что помечается `True` | Когда использовать |
|---|---|---|
| `"first"` (по умолчанию) | Все копии, кроме первой | Посчитать лишние строки |
| `"last"` | Все копии, кроме последней | Оставить самую позднюю версию |
| `False` | Все копии | Посмотреть повторы целиком |

Параметр `subset` сужает сравнение до части столбцов: `duplicated("trip_id")` или `duplicated(subset=["trip_id", "status"])`.

Вывод:

```text
Лишних полных повторов: 2
```

|   | trip_id | requested_at | zone_id | channel | status | distance_km | duration_min | fare_kzt |
|---|---|---|---|---|---|---|---|---|
| 8 | 1009 | 2026-10-05 10:00 | Z01 | phone | cancelled | NaN | NaN | NaN |
| 168 | 1009 | 2026-10-05 10:00 | Z01 | phone | cancelled | NaN | NaN | NaN |
| 43 | 1044 | 2026-10-06 15:30 | Z04 | app | completed | 14.8 | 55.7 | 3050.0 |
| 169 | 1044 | 2026-10-06 15:30 | Z04 | app | completed | 14.8 | 55.7 | 3050.0 |

`NaN` в обеих копиях считается совпадением: для `duplicated` пустое поле равно пустому полю.

**Код — удалить и проверить ключ:**

```python
trips = raw_trips.drop_duplicates().copy()
print("До:", len(raw_trips), "| После:", len(trips))
print("Каждый trip_id уникален:", trips["trip_id"].is_unique)
```

| Строка | Что происходит |
|---|---|
| `raw_trips.drop_duplicates()` | Новый DataFrame без полных повторов (оставлена первая копия). `raw_trips` не меняется |
| `.copy()` | Явная независимая копия. Дальше в `trips` будем добавлять столбцы, и это не должно касаться `raw_trips` |
| `trips = ...` | Рабочая таблица. С этого момента считаем только по ней |
| `len(...)` | Встроенная функция Python: число элементов, у DataFrame — число строк |
| `trips["trip_id"].is_unique` | Атрибут `Series` (без скобок): `True`, если все значения разные |

```text
До: 170 | После: 168
Каждый trip_id уникален: True
```

Порядок проверки: **полные повторы → удалить; повторы ключа после этого → разбираться.** Здесь после удаления полных повторов ключ уникален, значит конфликтующих версий одной заявки нет.

**Что вернётся.** `duplicated()` → `Series[bool]` той же длины, что таблица. `drop_duplicates()` → новый `DataFrame`, индекс со старыми номерами строк. Здесь ушли строки 168 и 169, поэтому индекс остался 0–167 без дыр. Если бы удалилась строка из середины, в индексе появился бы пропуск номера. `is_unique` → `bool`.

**Типичные ошибки:**

1. Вызвать `raw_trips.drop_duplicates()` без присваивания и думать, что таблица очистилась. Метод возвращает новую таблицу, исходная не меняется.
2. Проверить только полные повторы и пропустить конфликт ключа: две строки с одним ID и разной суммой `duplicated()` не поймает.
3. Удалить конфликт ключа через `drop_duplicates("trip_id")`. pandas оставит первую строку, даже если верная — вторая. Сначала выясните причину.

```python
print(tx.duplicated().sum())          # полные повторы
print(tx.duplicated("txn_id").sum())  # повторы ключа
```

### 1.5 assert: проверка, которая останавливает код

**Что это.** `assert` — инструкция самого Python (не pandas, не функция). Если условие истинно — ничего не происходит. Если ложно — выполнение останавливается с ошибкой `AssertionError` и вашим сообщением.

**Зачем.** Зафиксировать в коде то, что вы проверили глазами. Если данные поменяются (новая выгрузка, правка кода выше), вы узнаете об этом сразу, а не по странным цифрам в отчёте.

```python
assert trips["trip_id"].is_unique, "Один trip_id встретился несколько раз"
assert len(raw_trips) - len(trips) == 2, "Проверьте, какие строки удалены"
print("Проверки повторов пройдены.")
```

Синтаксис: `assert <условие>, <сообщение>`. Условие — любое выражение, дающее `True`/`False`. Сообщение — строка, необязательна, но без неё непонятно, что сломалось.

| Строка | Что проверяет |
|---|---|
| 1 | В рабочей таблице нет повторов ключа |
| 2 | Удалено ровно 2 строки — столько, сколько мы видели глазами. `==` — сравнение «равно», даёт `True`/`False` |
| 3 | Дойдём сюда, только если обе проверки прошли |

```text
Проверки повторов пройдены.
```

**Что вернётся.** Ничего, если всё в порядке. Если нет — ошибка, и ячейка дальше не выполняется. На банковских данных из 1.4:

```python
clean = tx.drop_duplicates()
assert clean["txn_id"].is_unique, "Один txn_id встретился несколько раз"
```

```text
AssertionError: Один txn_id встретился несколько раз
```

**Типичные ошибки:**

1. Скобки вокруг условия и сообщения: `assert (cond, "msg")`. Это **кортеж** из двух элементов, а непустой кортеж всегда истинен — проверка никогда не сработает. Python предупреждает: `assertion is always true, perhaps remove parentheses?`.
2. «Подогнать» assert под результат: поменять `== 2` на `== 3`, не разобравшись, откуда третья строка. Assert — страховка, а не способ убрать ошибку.
3. Проверять через assert данные в рабочем сервисе. При запуске `python -O` все `assert` отключаются. В ноутбуках и тестах — нормально; в production-коде — явная ошибка: `if not ...: raise ValueError(...)`.

### 1.6 Пропуски с понятным знаменателем

**Что это.** Таблица качества: сколько пропусков в каждом столбце и какая это доля от **уникальных заявок** (168), а не от сырых строк (170).

**Зачем.** «17% пропусков» без знаменателя ничего не значит. И важно понять, откуда пропуск: отмена (так и должно быть) или потерянное измерение (дефект данных).

**Код — таблица качества:**

```python
quality = pd.DataFrame({
    "missing_count": trips.isna().sum(),
    "missing_pct": trips.isna().mean() * 100,
})
quality.round(1)
```

| Строка | Что происходит |
|---|---|
| `pd.DataFrame({...})` | Создать таблицу из словаря: ключ → имя столбца, значение → данные столбца |
| `trips.isna().sum()` | `Series`: число пропусков по столбцам |
| `trips.isna().mean() * 100` | Среднее от `True`/`False` = доля `True`. `* 100` — процент; умножается каждый элемент |
| `})` | Запятая после последней пары разрешена — удобно добавлять строки |
| `quality.round(1)` | Округление только для показа; `quality` не меняется |

Обе `Series` имеют одинаковый индекс (имена столбцов `trips`), поэтому pandas ставит их рядом строка к строке.

|   | missing_count | missing_pct |
|---|---|---|
| trip_id | 0 | 0.0 |
| requested_at | 0 | 0.0 |
| zone_id | 0 | 0.0 |
| channel | 3 | 1.8 |
| status | 0 | 0.0 |
| distance_km | 29 | 17.3 |
| duration_min | 31 | 18.5 |
| fare_kzt | 29 | 17.3 |

После удаления повтора `1009` (отмена, все три поля пустые) пропусков в `distance_km` стало 29, а не 30.

**Код — откуда пропуски:**

```python
trips.groupby("status").agg(
    requests=("trip_id", "size"),
    known_duration=("duration_min", "count"),
)
```

| Часть | Что означает |
|---|---|
| `groupby("status")` | Разбить заявки на группы по статусу |
| `.agg(...)` | Посчитать для каждой группы несколько показателей |
| `requests=` | **Имя нового столбца** — придумываем сами |
| `("trip_id", "size")` | Кортеж: *какой столбец* взять и *какую функцию* применить |
| `"size"` | Число строк в группе, **включая** `NaN` → число заявок |
| `"count"` | Число **заполненных** значений → число известных длительностей |

> **Python: кортежи в `agg`.** `requests=("trip_id", "size")` — это именованный аргумент, значение которого — кортеж из двух строк. pandas читает его как «новый столбец `requests` = `size` по столбцу `trip_id`». Такая запись называется *named aggregation*. Скобки кортежа обязательны: без них два значения через запятую станут двумя разными аргументами.

|   | requests | known_duration |
|---|---|---|
| cancelled | 29 | 0 |
| completed | 139 | 137 |

Расшифровка: 31 пропуск в `duration_min` = 29 отмен (поездки не было — пропуск законный) + 2 завершённые поездки без измерения (дефект). Если заполнить их через `fillna(0)`, в среднюю длительность попадут 31 нулевая поездка, и среднее будет сильно занижено.

**Что вернётся.** `quality` → `DataFrame`, индекс — имена столбцов `trips`. `groupby().agg()` → `DataFrame`, индекс — значения `status`, столбцы — имена, которые вы задали.

**Типичные ошибки:**

1. Делить на 170 сырых строк вместо 168 заявок — доли получаются заниженными.
2. Путать `size` и `count`: `count` по столбцу с пропусками даст меньше заявок, чем есть на самом деле.
3. Заполнять пропуск нулём, не разобравшись в причине: «не было поездки» и «поездка длилась 0 минут» — разные вещи.

**Банковский пример.** Справочник клиентов: у части нет email. Сколько клиентов в сегменте и у скольких email известен?

```python
cl = pd.DataFrame({
    "client_id": [11, 12, 13, 14],
    "segment":   ["mass", "premium", "mass", "mass"],
    "email":     ["a@x.kz", None, "c@x.kz", None],
})
cl.groupby("segment").agg(clients=("client_id", "size"), with_email=("email", "count"))
```

|   | clients | with_email |
|---|---|---|
| mass | 3 | 2 |
| premium | 1 | 0 |

`(cl.isna().mean() * 100).round(1)` → у `email` 50.0% пропусков. Для рассылки это значит: охват — половина базы, а premium-клиентов не достанем вообще.

### 2.2 Индекс: iloc, loc и set_index

**Что это.** Индекс — столбец меток слева от таблицы, адрес строки. По умолчанию это номера 0, 1, 2… `set_index` делает адресом обычный столбец, например `trip_id`.

**Зачем.** Чтобы обращаться к строке по смыслу: «заявка 1002», а не «строка на второй позиции». Позиции меняются после фильтра и сортировки, а ID заявки — нет.

Два способа выбора:

| | `iloc` | `loc` |
|---|---|---|
| Выбирает по | **позиции** (0, 1, 2…) | **метке индекса** или маске |
| Срез `[0:3]` | Правая граница **не** входит: 0, 1, 2 | Правая граница **входит** |
| После фильтра/сортировки | Позиции пересчитываются | Метки остаются прежними |

**Код — выбор по позиции:**

```python
trips.iloc[0:3, 0:5]
```

До запятой — строки, после — столбцы. `0:3` — **срез** Python: от 0 до 3, не включая 3. Получаем 3 строки и 5 столбцов.

|   | trip_id | requested_at | zone_id | channel | status |
|---|---|---|---|---|---|
| 0 | 1001 | 2026-10-05 06:00 | Z01 | app | cancelled |
| 1 | 1002 | 2026-10-05 06:30 | Z03 | phone | completed |
| 2 | 1003 | 2026-10-05 07:00 | Z02 | app | completed |

**Код — `trip_id` как индекс:**

```python
by_id = trips.set_index("trip_id", verify_integrity=True)
by_id.loc[[1002, 1003], ["zone_id", "status", "fare_kzt"]]
```

| Часть | Что делает |
|---|---|
| `trips.set_index("trip_id")` | Метод DataFrame: новая таблица, где `trip_id` стал индексом и **ушёл из столбцов** |
| `verify_integrity=True` | Аргумент: проверить, что метки уникальны. Если есть повторы — `ValueError` |
| `by_id = ...` | Результат сохраняем в новую переменную. `trips` не меняется |
| `.loc[[1002, 1003], [...]]` | Строки с метками 1002 и 1003, три столбца. Оба списка — обычные списки Python |

|   | zone_id | status | fare_kzt |
|---|---|---|---|
| **trip_id** | | | |
| 1002 | Z03 | completed | 1100.0 |
| 1003 | Z02 | completed | 3450.0 |

Над индексом появилось его имя — `trip_id`.

**Код — метка и позиция дают одну строку:**

```python
display(by_id.loc[1002, ["status", "fare_kzt"]])
display(by_id.iloc[1][["status", "fare_kzt"]])
```

- `by_id.loc[1002, [...]]` — строка с **меткой** 1002, два столбца.
- `by_id.iloc[1]` — строка на **позиции** 1 (вторая по счёту) целиком, как `Series`; затем `[[...]]` выбирает из неё два значения.

Оба вывода одинаковы, потому что заявка 1002 стоит второй:

```text
status      completed
fare_kzt       1100.0
Name: 1002, dtype: object
```

`Name: 1002` — метка строки, из которой взята эта `Series`. `dtype: object` — в одной `Series` оказались строка и число, поэтому общий тип — `object`.

**Что вернётся.**

| Запись | Результат |
|---|---|
| `df.set_index("col")` | Новый `DataFrame`, `col` — индекс |
| `df.loc[[метки], [столбцы]]` | `DataFrame` |
| `df.loc[метка, [столбцы]]` | `Series` (одна строка) |
| `df.loc[метка, "столбец"]` | Одно значение (скаляр) |
| `df.iloc[позиция]` | `Series` — строка целиком |

Обратная операция — `by_id.reset_index()`: индекс снова становится столбцом, а слева появляются 0, 1, 2…

**Типичные ошибки:**

1. `by_id.iloc[1010]` для поиска заявки 1010 → `IndexError: single positional indexer is out-of-bounds`. `iloc` ищет 1011-ю по счёту строку, а их всего 168.
2. `by_id.loc[1]` → `KeyError: 1`. После `set_index` меток 0, 1, 2 больше нет — есть 1001, 1002…
3. `set_index` на таблице с повторами без проверки. С `verify_integrity=True` на `raw_trips` сразу видно, в чём проблема: `ValueError: Index has duplicate keys: Index([1009, 1044], ...)`. В pandas 3.0 этот аргумент объявлен устаревшим — там проверяют так: `assert by_id.index.is_unique`.

**Банковский пример.** Справочник клиентов с адресом строки по `client_id`:

```python
clients = pd.DataFrame({
    "client_id": [11, 12, 13, 14],
    "name":      ["Айгерим", "Данияр", "Марат", "Салтанат"],
    "segment":   ["mass", "premium", "mass", "mass"],
})
by_client = clients.set_index("client_id")
by_client.loc[[12, 14], ["name", "segment"]]
```

|   | name | segment |
|---|---|---|
| **client_id** | | |
| 12 | Данияр | premium |
| 14 | Салтанат | mass |

`by_client.loc[13, "segment"]` → `'mass'` (одно значение). Это как `SELECT segment FROM clients WHERE client_id = 13` по первичному ключу.

### 2.3 Фильтры по условиям

Коротко: условие над столбцом даёт **булеву маску** — `Series` из `True`/`False`, по одному значению на строку. `df.loc[маска]` оставляет строки с `True`.

```python
completed_mask = trips["status"] == "completed"
completed_mask.head(8)
```

`==` — сравнение «равно» (одно `=` — присваивание). Сравнение применяется к каждой строке сразу.

```text
0    False
1     True
2     True
3     True
4     True
5     True
6     True
7     True
Name: status, dtype: bool
```

```python
completed = trips.loc[completed_mask].copy()
print("Завершённых поездок:", len(completed))
```

```text
Завершённых поездок: 139
```

`.copy()` здесь обязателен по делу: дальше в `completed` будут добавлять столбцы. Без копии pandas 2.2 выдаёт `SettingWithCopyWarning` — не уверен, меняете вы копию или кусок исходной таблицы. (В pandas 3.0 предупреждения уже нет, но `.copy()` по-прежнему делает намерение явным.)

**Несколько условий:**

```python
long_trips = trips.loc[
    (trips["status"] == "completed") & (trips["distance_km"] >= 10),
    ["trip_id", "distance_km", "duration_min", "fare_kzt"],
]
print("Найдено:", len(long_trips))
long_trips.head()
```

| Строка | Что делает |
|---|---|
| `trips.loc[` | Открываем выбор; перенос строки внутри скобок Python разрешает |
| `(...) & (...)` | Обе маски, `&` — «И» поэлементно. Каждое условие в своих скобках |
| `["trip_id", ...]` | После запятой — какие столбцы оставить |
| `]` | Закрываем `loc` |

```text
Найдено: 70
```

|   | trip_id | distance_km | duration_min | fare_kzt |
|---|---|---|---|---|
| 2 | 1003 | 15.8 | 56.2 | 3450.0 |
| 3 | 1004 | 11.8 | 32.6 | 2650.0 |
| 5 | 1006 | 15.1 | 59.4 | 3150.0 |
| 6 | 1007 | 10.5 | 28.7 | 2450.0 |
| 10 | 1011 | 15.8 | 53.8 | 3400.0 |

Индекс слева — старые номера строк `trips`, с пропусками. Поэтому для поиска внутри `long_trips` нужен `loc` по метке или `iloc` по позиции — и это разные строки.

| Оператор | Смысл | Пример |
|---|---|---|
| `&` | И | `(a > 1) & (b == "x")` |
| `\|` | ИЛИ | `(a > 1) \| (b == "x")` |
| `~` | НЕ | `~(b == "x")` |
| `.isin([...])` | Одно из значений | `df["channel"].isin(["app", "web"])` |

**`isin` вместо цепочки ИЛИ:**

```python
digital_requests = trips.loc[trips["channel"].isin(["app", "web"])]
print("Из app/web:", len(digital_requests))
digital_requests["status"].value_counts()
```

`isin` — метод `Series`, принимает список допустимых значений и возвращает маску. `value_counts()` — сколько раз встречается каждое значение.

```text
Из app/web: 131

status
completed    111
cancelled     20
Name: count, dtype: int64
```

**Что вернётся.** Маска → `Series[bool]` той же длины, что таблица. `df.loc[маска]` → `DataFrame` с подмножеством строк и **исходными** метками индекса. `value_counts()` → `Series`: значение → количество, по убыванию.

**Типичные ошибки:**

1. `and`/`or` вместо `&`/`|` → `ValueError: The truth value of a Series is ambiguous`. `and` из Python ждёт одно `True`/`False`, а получает 168 значений.
2. Без скобок: `trips["status"] == "completed" & trips["distance_km"] >= 10` → `TypeError: Cannot perform 'rand_' ...`. `&` выполняется раньше `==` и `>=`, и Python пытается сделать «И» между строкой `"completed"` и столбцом.
3. Длинная цепочка `(c == "app") | (c == "web") | ...` вместо `isin` — легко пропустить скобку или значение.

**Банковский пример.** Успешные транзакции от 500 000 ₸ — кандидаты на проверку по финмониторингу:

```python
tx = pd.DataFrame({
    "txn_id":     [501, 502, 503, 504, 505, 506],
    "client_id":  [11, 12, 11, 13, 12, 14],
    "txn_type":   ["card", "transfer", "atm", "transfer", "card", "card"],
    "amount_kzt": [15000, 520000, 40000, 75000, 2300, 610000],
    "status":     ["ok", "ok", "ok", "declined", "ok", "ok"],
})
tx.loc[(tx["status"] == "ok") & (tx["amount_kzt"] >= 500000), ["txn_id", "client_id", "amount_kzt"]]
```

|   | txn_id | client_id | amount_kzt |
|---|---|---|---|
| 1 | 502 | 12 | 520000 |
| 5 | 506 | 14 | 610000 |

Карта или перевод, кроме отклонённых:
`tx.loc[tx["txn_type"].isin(["card", "transfer"]) & ~(tx["status"] == "declined"), "txn_id"].tolist()` → `[501, 502, 505, 506]`.

### 2.4 Пропуски в фильтре и сортировка

**Код — найти пропуски:**

```python
missing_duration = completed.loc[
    completed["duration_min"].isna(),
    ["trip_id", "status", "distance_km", "duration_min"],
]
missing_duration
```

`isna()` здесь — маска для фильтра. Это две завершённые поездки с потерянной длительностью из части 1:

|   | trip_id | status | distance_km | duration_min |
|---|---|---|---|---|
| 9 | 1010 | completed | 8.6 | NaN |
| 76 | 1077 | completed | 17.9 | NaN |

Сравнение с `None` не работает: `(trips["duration_min"] == None).sum()` даёт `0`, хотя пропусков 31. `NaN` не равен ничему, даже самому себе. Обратный фильтр — `notna()`.

**Код — сортировка:**

```python
completed.sort_values("fare_kzt", ascending=False)[
    ["trip_id", "distance_km", "fare_kzt"]
].head(5)
```

- `sort_values("fare_kzt", ascending=False)` — метод: новая таблица, отсортированная по убыванию оплаты. `completed` не меняется.
- `[[...]]` — затем выбрать три столбца, `.head(5)` — первые пять.

|   | trip_id | distance_km | fare_kzt |
|---|---|---|---|
| 14 | 1015 | 18.5 | 3900.0 |
| 67 | 1068 | 18.0 | 3850.0 |
| 57 | 1058 | 17.8 | 3800.0 |
| 143 | 1144 | 18.0 | 3800.0 |
| 137 | 1138 | 18.0 | 3800.0 |

**Типичные ошибки:** `== None` или `== np.nan` вместо `isna()` — фильтр молча возвращает пустую таблицу; ждать, что `sort_values` изменит исходную таблицу; забыть `ascending=False` и получить самые дешёвые поездки вместо самых дорогих.

### 2.5 Новые столбцы без циклов

**Что это.** Новый столбец создаётся присваиванием: `df["новое_имя"] = выражение над столбцами`. Операция применяется ко всем строкам сразу — это называется **векторизация**.

**Зачем.** Производные показатели (часы вместо минут, оплата за км) нужны для отчёта и моделей. Цикл `for` по строкам в pandas длиннее и в разы медленнее.

**Код — минуты в часы:**

```python
analysis = completed.copy()
analysis["duration_hours"] = analysis["duration_min"] / 60
analysis[["duration_min", "duration_hours"]].head().round(2)
```

| Строка | Что делает |
|---|---|
| `analysis = completed.copy()` | Отдельная таблица для учебных признаков; `completed` остаётся как был |
| `analysis["duration_hours"] = ...` | Если столбца нет — создаётся, если есть — перезаписывается |
| `analysis["duration_min"] / 60` | Каждое значение делится на 60; `NaN / 60` остаётся `NaN` |

|   | duration_min | duration_hours |
|---|---|---|
| 1 | 12.7 | 0.21 |
| 2 | 56.2 | 0.94 |
| 3 | 32.6 | 0.54 |
| 4 | 28.7 | 0.48 |
| 5 | 59.4 | 0.99 |

**Код — оплата за километр с проверкой:**

```python
assert analysis["distance_km"].gt(0).all(), "Есть нулевая или отрицательная дистанция"
analysis["fare_per_km"] = analysis["fare_kzt"] / analysis["distance_km"]
analysis[["distance_km", "fare_kzt", "fare_per_km"]].head().round(2)
```

| Часть | Что делает |
|---|---|
| `.gt(0)` | Метод `Series`, «greater than»: то же, что `> 0`. Маска |
| `.all()` | Метод: `True`, если **все** значения маски `True` |
| `assert ..., "..."` | Остановить код, если есть дистанция ≤ 0 (см. 1.5) |
| `fare_kzt / distance_km` | Деление столбца на столбец — строка на строку, по индексу |

|   | distance_km | fare_kzt | fare_per_km |
|---|---|---|---|
| 1 | 3.0 | 1100.0 | 366.67 |
| 2 | 15.8 | 3450.0 | 218.35 |
| 3 | 11.8 | 2650.0 | 224.58 |
| 4 | 9.7 | 2250.0 | 231.96 |
| 5 | 15.1 | 3150.0 | 208.61 |

Как читать: короткая поездка 1002 «дороже за км» (366.67), потому что в сумме, скорее всего, есть фиксированная часть. `fare_per_km` — расчётный показатель, а не доказанный тариф.

**Что вернётся.** Присваивание столбца ничего не возвращает и меняет таблицу на месте: в `analysis` стало на 2 столбца больше. Арифметика над `Series` → новая `Series` той же длины.

**Типичные ошибки:**

1. Делить без проверки на ноль. pandas **не** выдаёт ошибку: `1100 / 0` → `inf`. Бесконечность молча испортит среднее. Поэтому сначала `assert ... .gt(0).all()`.
2. Добавлять столбец в результат фильтра без `.copy()` → `SettingWithCopyWarning` (pandas 2.x).
3. «Чинить» пропуски арифметикой: `NaN` в `duration_min` даст `NaN` в часах — так и должно быть. Неизвестное измерение не восстанавливаем.

**Банковский пример.** Комиссия 0,5% и флаг крупной операции для успешных транзакций (`tx` из 2.3):

```python
ok = tx.loc[tx["status"] == "ok"].copy()
ok["fee_kzt"] = ok["amount_kzt"] * 0.005
ok["is_large"] = ok["amount_kzt"] >= 500000
ok[["txn_id", "amount_kzt", "fee_kzt", "is_large"]]
```

|   | txn_id | amount_kzt | fee_kzt | is_large |
|---|---|---|---|---|
| 0 | 501 | 15000 | 75.0 | False |
| 1 | 502 | 520000 | 2600.0 | True |
| 2 | 503 | 40000 | 200.0 | False |
| 4 | 505 | 2300 | 11.5 | False |
| 5 | 506 | 610000 | 3050.0 | True |

Столбцом можно сделать и маску: `is_large` хранит `True`/`False`, потом по нему удобно фильтровать и считать.

### Итоги части 2

#### Шпаргалка

| Запись | Что делает |
|---|---|
| `df["a"]` | Один столбец → `Series` |
| `df[["a", "b"]]` | Несколько столбцов → `DataFrame` |
| `type(x).__name__` | Имя класса объекта |
| `df.iloc[0:3, 0:5]` | По позициям; правая граница не входит |
| `df.set_index("id")` | Новая таблица, `id` — индекс |
| `df.set_index("id", verify_integrity=True)` | То же + ошибка при повторах (pandas 2.x) |
| `df.loc[[1002, 1003], ["a", "b"]]` | По меткам индекса |
| `df.loc[1002, "a"]` | Одно значение |
| `df.reset_index()` | Индекс обратно в столбец |
| `df["a"] == "x"` | Булева маска |
| `df.loc[маска].copy()` | Отфильтровать и сделать независимую копию |
| `(усл1) & (усл2)`, `\|`, `~` | И, ИЛИ, НЕ — каждое условие в скобках |
| `df["a"].isin([...])` | Значение из списка |
| `df["a"].isna()` / `.notna()` | Маска пропусков / заполненных |
| `s.value_counts()` | Частоты значений |
| `df.sort_values("a", ascending=False)` | Сортировка по убыванию, новая таблица |
| `df["new"] = df["a"] / 60` | Новый столбец без цикла |
| `s.gt(0).all()` | Все значения больше 0? |

#### Выжимка для конспекта

1. `["a"]` → Series, `[["a"]]` → DataFrame.
2. `iloc` — позиция, `loc` — метка. После фильтра это разные вещи.
3. `set_index("trip_id")` — адрес строки по смыслу; столбец уходит в индекс. Ключ должен быть уникален.
4. `by_id.iloc[1010]` ≠ «заявка 1010».
5. Фильтр: маска → `loc[маска]`. Несколько условий: `&` `|` `~`, каждое в скобках, не `and`/`or`.
6. Много значений одного поля → `isin`.
7. Пропуски ищем через `isna()`, не `== None`.
8. После фильтра, если будем добавлять столбцы, — `.copy()`.
9. Новый столбец — одна строка без цикла. Перед делением проверить знаменатель: деление на 0 даёт `inf`, а не ошибку.

#### Упражнения

1. Найдите заявку `1077` через `by_id.loc`. Затем найдите её же в `trips` через `iloc` — на какой она позиции и почему?
2. Отберите завершённые поездки из `phone` или `web` короче 5 км. Покажите ID, канал, дистанцию и оплату, отсортируйте по оплате по убыванию, посчитайте строки.
3. Добавьте в `analysis` столбец `speed_kmh` (дистанция / часы). Сколько в нём `NaN` и почему? Выведите три самые быстрые поездки и проверьте `assert`, что скорость везде, где она известна, больше 0.

#### Где пригодится в AI Engineering

- **Фильтры по метаданным в RAG:** перед семантическим поиском документы сужают условиями (продукт, дата, язык) — та же логика маски, только в запросе к векторной базе.
- **Подготовка признаков и контекста:** производные столбцы (длина текста, сумма, флаги) считаются векторно перед отправкой в модель или в eval-набор.
- **Доступ по ID:** индекс по ключу — как поиск документа или клиента по первичному ключу перед тем, как собрать для LLM контекст по конкретной сущности.

## Часть 3. groupby и первый график

Разделы ноутбука 6–7. Таблицы: `trips` (168 заявок) и `completed` (139 завершённых поездок) из части 2.

### 3.1 groupby: разделить, посчитать, собрать

**Что это.** `groupby` выполняет три шага: **разделить** строки на группы по значению столбца → **посчитать** показатель в каждой группе → **собрать** результаты в маленькую таблицу.

```text
trips (168 строк)
   │ разделить по channel
   ├── app   (116 строк) → size → 116
   ├── phone  (34 строки) → size →  34
   ├── web    (15 строк)  → size →  15
   └── NaN     (3 строки) → size →   3
   │ собрать
   ▼
Series: channel → число заявок
```

**Зачем.** Ответить на один вопрос сразу для каждой категории: сколько заявок из каждого канала, сколько денег в каждой зоне.

```python
requests_by_channel = trips.groupby("channel", dropna=False).size()
requests_by_channel
```

| Часть | Что делает |
|---|---|
| `trips.groupby("channel")` | Метод DataFrame. Возвращает объект `DataFrameGroupBy` — «разложенные по группам» строки. Сам по себе ничего не показывает |
| `dropna=False` | Аргумент: строки с `NaN` в `channel` — отдельная группа, а не выброшены |
| `.size()` | Метод группировки: число строк в каждой группе |

```text
channel
app      116
phone     34
web       15
NaN        3
dtype: int64
```

**Что вернётся.** `groupby(...).size()` → `Series`: индекс — значения ключа группировки, значения — количества.

**Типичные ошибки:**

1. Забыть `dropna=False`. По умолчанию `groupby` молча выбрасывает `NaN`-группу: получится 116 + 34 + 15 = 165 заявок вместо 168, и три заявки исчезнут из отчёта.
2. Смотреть на `trips.groupby("channel")` и ждать таблицу. Без функции (`size`, `sum`, `agg`…) результата нет.
3. Группировать по `trip_id` или другому уникальному ключу: каждая группа — одна строка, сводки не получится.

**Банковский пример.** Число транзакций по типу, тип неизвестен у одной:

```python
tx = pd.DataFrame({
    "txn_id":     [501, 502, 503, 504, 505, 506, 507, 508],
    "client_id":  [11, 12, 11, 13, 12, 14, 11, 13],
    "txn_type":   ["card", "transfer", "atm", "transfer", "card", "card", None, "card"],
    "amount_kzt": [15000.5, 520000, 40000, 75000, 2300.25, 610000, 9000, 12500.1],
})
tx.groupby("txn_type", dropna=False).size()
```

```text
txn_type
atm         1
card        4
transfer    2
NaN         1
dtype: int64
```

Транзакция без типа — сигнал для интеграции: источник не передаёт тип операции.

### 3.2 Доли и знаменатель

Коротко: `value_counts(normalize=True)` делит каждое количество на общее число значений — получается доля.

```python
(trips["status"].value_counts(normalize=True) * 100).round(1)
```

Внешние скобки обязательны. Без них `.round(1)` вызовется у числа `100`, и код упадёт с ошибкой: у целого числа Python нет метода `round`.

```text
status
completed    82.7
cancelled    17.3
Name: proportion, dtype: float64
```

Знаменатель — **все 168 уникальных заявок**. Доля отмен **в приложении** — другой вопрос с другим знаменателем: только заявки из `app`. Перед любой долей спросите себя: «процент от чего?»

Подвох: `value_counts` по умолчанию тоже пропускает `NaN`. Для `channel` нужно `value_counts(dropna=False)`, иначе знаменатель станет 165.

### 3.3 Несколько метрик сразу: agg

**Что это.** `agg` после `groupby` считает несколько показателей за один проход. Запись `имя=("столбец", "функция")` — та же named aggregation, что в [1.6](#16-пропуски-с-понятным-знаменателем).

**Зачем.** Показатель без числа наблюдений вводит в заблуждение. Медиана по 3 поездкам и по 97 — разная надёжность, и это должно быть видно в одной таблице.

```python
channel_summary = trips.groupby("channel", dropna=False).agg(
    requests=("trip_id", "size"),
    known_duration=("duration_min", "count"),
    median_duration_min=("duration_min", "median"),
)
channel_summary.round(1)
```

| Строка | Что считает |
|---|---|
| `requests=("trip_id", "size")` | Все заявки группы, включая отмены |
| `known_duration=("duration_min", "count")` | Сколько длительностей известно |
| `median_duration_min=("duration_min", "median")` | Медиана **только по известным** длительностям; `NaN` пропускаются |

|   | requests | known_duration | median_duration_min |
|---|---|---|---|
| **channel** | | | |
| app | 116 | 97 | 31.6 |
| phone | 34 | 24 | 28.8 |
| web | 15 | 13 | 24.7 |
| NaN | 3 | 3 | 54.7 |

Как читать: в `app` 116 заявок, но медиана посчитана по 97 длительностям (остальные — отмены или потерянные измерения). Медиана `NaN`-канала 54.7 — по трём поездкам, выводы по ней делать нельзя.

Какие функции можно писать строкой: `"size"`, `"count"`, `"sum"`, `"mean"`, `"median"`, `"min"`, `"max"`, `"nunique"` (число уникальных значений).

**Что вернётся.** `DataFrame`: индекс — группы, столбцы — имена, которые вы задали слева от `=`.

**Типичные ошибки:**

1. Ставить в одну таблицу «все заявки» и «медиану по поездкам» без числа измерений — читатель решит, что медиана посчитана по всем 116.
2. Чужое имя функции: `("fare_kzt", "avg")` → `AttributeError: 'SeriesGroupBy' object has no attribute 'avg'`. В pandas это `"mean"` (`AVG` — из SQL).
3. Забыть кортеж: `requests="trip_id", "size"` — синтаксическая ошибка Python.

### 3.4 Сводка по деньгам и контроль сумм

**Что это.** Сводка по завершённым поездкам: число поездок, сумма и медиана оплат по зоне, плюс проверка, что группировка ничего не потеряла.

**Зачем.** Деньги считают **только по завершённым** поездкам — поэтому берём `completed`, а не `trips`. Контроль «сумма частей = целое» ловит потерю строк (например, из-за `NaN` в ключе).

```python
completed_by_zone = completed.groupby("zone_id").agg(
    completed_trips=("trip_id", "size"),
    payments_kzt=("fare_kzt", "sum"),
    median_fare_kzt=("fare_kzt", "median"),
)
completed_by_zone.sort_values("payments_kzt", ascending=False)
```

|   | completed_trips | payments_kzt | median_fare_kzt |
|---|---|---|---|
| **zone_id** | | | |
| Z04 | 39 | 84800.0 | 2250.0 |
| Z01 | 26 | 64750.0 | 2400.0 |
| Z03 | 30 | 63700.0 | 1925.0 |
| Z02 | 27 | 60900.0 | 2200.0 |
| Z05 | 16 | 31550.0 | 1725.0 |
| Z99 | 1 | 2700.0 | 2700.0 |

`Z99` — одна поездка с кодом зоны, которого, как выяснится в части 4, нет в справочнике.

Что **нельзя** утверждать по этой таблице: что `Z04` — самая прибыльная или лучшая зона. Там просто больше поездок (39). Сумма оплат ≠ прибыль: расходов и возвратов в данных нет.

**Код — проверка, что ничего не потеряли:**

```python
assert completed_by_zone["completed_trips"].sum() == len(completed)
assert np.isclose(completed_by_zone["payments_kzt"].sum(), completed["fare_kzt"].sum())
print("Группы не потеряли поездки и суммы.")
```

| Строка | Что проверяет |
|---|---|
| 1 | Сумма поездок по зонам = 139 завершённым поездкам. Целые числа сравниваем через `==` |
| 2 | Сумма оплат по зонам = сумме оплат всех завершённых. Дробные — через `np.isclose` |
| 3 | Печатается, только если обе проверки прошли |

```text
Группы не потеряли поездки и суммы.
```

> **NumPy: `np.isclose(a, b)`** — функция NumPy (`np` из импорта в 1.1). Возвращает `True`, если `a` и `b` равны с точностью до крошечной погрешности. Нужна, потому что дробные числа хранятся в двоичном виде неточно: в Python `0.1 + 0.2 == 0.3` → `False`, а `np.isclose(0.1 + 0.2, 0.3)` → `True`. Суммы, сложенные в разном порядке, могут разойтись в последних знаках — `==` упадёт без реальной ошибки.

**Типичные ошибки:**

1. Считать деньги по `trips`: отмены дадут `NaN`, `sum` их пропустит, а `size` посчитает отмены как поездки — число поездок будет завышено.
2. Сравнивать дробные суммы через `==` — ложное падение проверки.
3. Делать вывод по одной сумме без количества: зона с одной дорогой поездкой (`Z99`) по медиане выглядит «самой дорогой».

**Банковский пример.** Сводка по клиентам (`tx` из 3.1) и контроль, что обороты не потерялись:

```python
by_client = tx.groupby("client_id").agg(
    txn_count=("txn_id", "size"),
    total_kzt=("amount_kzt", "sum"),
    median_kzt=("amount_kzt", "median"),
)
by_client.sort_values("total_kzt", ascending=False)
```

|   | txn_count | total_kzt | median_kzt |
|---|---|---|---|
| **client_id** | | | |
| 14 | 1 | 610000.00 | 610000.000 |
| 12 | 2 | 522300.25 | 261150.125 |
| 13 | 2 | 87500.10 | 43750.050 |
| 11 | 3 | 64000.50 | 15000.500 |

```python
assert by_client["txn_count"].sum() == len(tx)
assert np.isclose(by_client["total_kzt"].sum(), tx["amount_kzt"].sum())
```

Обе проверки проходят. Клиент 14 лидирует по обороту, но у него одна операция — для скоринга это совсем другой профиль, чем у клиента 11 с тремя мелкими.

### 3.5 Первый график: столбчатая диаграмма

**Что это.** Столбчатая диаграмма (bar chart) сравнивает количество по категориям. Сначала готовим маленькую таблицу, потом рисуем её.

**Зачем.** Быстро увидеть соотношение каналов и не потерять неизвестный канал.

```python
channel_counts = trips["channel"].fillna("unknown").value_counts()
ax = channel_counts.plot.bar(color="#2563EB", rot=0)
ax.set_title("Заявки по каналам • учебные данные")
```

| Часть | Что делает |
|---|---|
| `fillna("unknown")` | Заменить `NaN` текстом `"unknown"` — только в этом выражении, `trips` не меняется. Иначе `value_counts` выбросит пропуски и столбца не будет |
| `.value_counts()` | `Series`: канал → количество, по убыванию |
| `channel_counts.plot.bar(...)` | Метод pandas: рисует столбцы через matplotlib. `.plot` — атрибут-«меню» графиков, `.bar` — метод из него |
| `color="#2563EB"` | Цвет в HEX-записи (синий) |
| `rot=0` | Подписи по оси X без наклона |
| `ax = ...` | Метод возвращает объект **Axes** — область графика. Его сохраняем, чтобы настроить подписи |
| `ax.set_title(...)` | Метод Axes: заголовок |

```python
ax.set_xlabel("Канал заказа")
ax.set_ylabel("Количество уникальных заявок")
ax.grid(axis="y", alpha=0.2)
plt.tight_layout()
plt.show()
```

| Строка | Что делает |
|---|---|
| `ax.set_xlabel` / `ax.set_ylabel` | Подписи осей |
| `ax.grid(axis="y", alpha=0.2)` | Горизонтальные линии сетки; `alpha` — прозрачность (0 — невидимо, 1 — полностью) |
| `plt.tight_layout()` | Функция matplotlib: подогнать поля, чтобы подписи не обрезались |
| `plt.show()` | Показать график. В Jupyter обычно и так покажется, в обычном `.py`-скрипте без неё окна не будет |

> **matplotlib: Figure и Axes.** **Figure** — весь «лист» с картинкой (размер задали в 1.1: 8×4). **Axes** — одна область с осями внутри листа. Методы `ax.set_...` настраивают конкретный график, функции `plt.…` работают с текущим листом целиком.

**Что вернётся.** `plot.bar` → объект `Axes`. В ноутбуке печатается `<Figure size 880x440 with 1 Axes>` (8×4 дюйма × 110 dpi = 880×440 пикселей) и сама картинка.

На графике те же числа, что в 3.1; `NaN` подписан как `unknown`.

Высокий столбец `app` — это **объём**, а не качество приложения. О качестве говорят доли отмен внутри канала и длительности, а не число заявок.

**Типичные ошибки:**

1. Строить график без `fillna` — неизвестный канал пропадёт без следа.
2. Рисовать по сырой таблице `raw_trips` с повторами — столбцы будут завышены.
3. Подписать ось просто «Количество» — непонятно, заявки это или поездки.

Разделы ноутбука 8–10 (занятие 2). Цель: добавить к заявкам названия зон из второго файла и доказать, что при этом не потерялась и не размножилась ни одна заявка.

### 4.1 Даты: to_datetime и .dt

**Что это.** `pd.to_datetime` превращает текст вида `"2026-10-05 06:00"` в настоящий тип даты-времени. После этого через `.dt` можно достать день, час, день недели.

**Зачем.** CSV хранит всё текстом. Пока дата — строка, нельзя взять час, посчитать разницу во времени или надёжно отфильтровать период. Название столбца `requested_at` тип не меняет.

**Код — преобразование:**

```python
print("Тип до:", trips["requested_at"].dtype)
trips["requested_at"] = pd.to_datetime(
    trips["requested_at"], format="%Y-%m-%d %H:%M", errors="raise"
)
print("Тип после:", trips["requested_at"].dtype)
```

| Часть | Что делает |
|---|---|
| `.dtype` | Атрибут `Series`: тип данных столбца |
| `pd.to_datetime(...)` | Функция pandas: строки → даты-время |
| `format="%Y-%m-%d %H:%M"` | Шаблон, по которому читать строку |
| `errors="raise"` | Если строка не подходит под шаблон — остановить код с ошибкой |
| `trips["requested_at"] = ...` | Перезаписать столбец новым значением |

```text
Тип до: object
Тип после: datetime64[ns]
```

`datetime64[ns]` — тип даты-времени pandas, точность до наносекунд (в pandas 3.0 — `[us]`, микросекунды).

Коды шаблона (это стандарт Python, не только pandas):

| Код | Значение | Пример |
|---|---|---|
| `%Y` | Год, 4 цифры | `2026` |
| `%m` | Месяц, 2 цифры | `10` |
| `%d` | День, 2 цифры | `05` |
| `%H` | Час, 00–23 | `06` |
| `%M` | Минуты | `30` |
| `%S` | Секунды | `00` |

Варианты `errors`:

| `errors=` | Что при неподходящей строке |
|---|---|
| `"raise"` (по умолчанию) | `ValueError`, код остановится |
| `"coerce"` | Значение станет `NaT` (пропуск для дат), код продолжится молча |

В следующих выгрузках можно читать дату сразу: `pd.read_csv(путь, parse_dates=["requested_at"])`. В ноутбуке шаги разделены, чтобы увидеть смену типа.

**Код — день и час:**

```python
trips["request_date"] = trips["requested_at"].dt.date
trips["request_hour"] = trips["requested_at"].dt.hour
trips[["trip_id", "requested_at", "request_date", "request_hour"]].head()
```

- `.dt` — атрибут-«меню» у `Series` с датами (как `.plot` у графиков). Работает только с типом `datetime64`.
- `.dt.date` — только дата. Значения — объекты `date` из Python, поэтому тип столбца — `object`.
- `.dt.hour` — час, целое число 0–23.

|   | trip_id | requested_at | request_date | request_hour |
|---|---|---|---|---|
| 0 | 1001 | 2026-10-05 06:00:00 | 2026-10-05 | 6 |
| 1 | 1002 | 2026-10-05 06:30:00 | 2026-10-05 | 6 |
| 2 | 1003 | 2026-10-05 07:00:00 | 2026-10-05 | 7 |
| 3 | 1004 | 2026-10-05 07:30:00 | 2026-10-05 | 7 |
| 4 | 1005 | 2026-10-05 08:00:00 | 2026-10-05 | 8 |

Другие полезные свойства: `.dt.day_name()` → `'Monday'`, `.dt.dayofweek` → 0 для понедельника, `.dt.normalize()` → полночь того же дня, но с сохранением типа `datetime64` (удобнее для группировки, чем `.dt.date`).

**Что вернётся.** `to_datetime` → `Series` типа `datetime64[ns]`. `.dt.hour` → `Series` целых. `.dt.date` → `Series` типа `object` с датами Python.

**Типичные ошибки:**

1. Вызвать `.dt` у строкового столбца → `AttributeError: Can only use .dt accessor with datetimelike values`. Сначала `to_datetime`.
2. `errors="coerce"` без проверки: неподходящие строки тихо станут `NaT`. Если используете `coerce`, следом посчитайте `.isna().sum()`.
3. Не указать `format`. pandas будет угадывать, и `05.10.2026` может прочитаться как 10 мая. С явным шаблоном и `raise` неподходящая строка сразу даёт ошибку: `time data "05.10.2026 06:30" doesn't match format "%Y-%m-%d %H:%M"`.

**Банковский пример.** Ночные операции — частый признак в антифроде:

```python
ops = pd.DataFrame({
    "op_dt":      ["2026-11-02 02:15", "2026-11-02 11:40", "2026-11-03 04:05", "2026-11-03 19:20"],
    "amount_kzt": [450000, 12000, 300000, 8000],
})
ops["op_dt"] = pd.to_datetime(ops["op_dt"], format="%Y-%m-%d %H:%M")
ops["op_hour"] = ops["op_dt"].dt.hour
ops["is_night"] = ops["op_hour"].between(0, 5)
```

`between(0, 5)` — метод `Series`: `True`, если значение от 0 до 5 включительно.

|   | op_dt | amount_kzt | op_hour | is_night |
|---|---|---|---|---|
| 0 | 2026-11-02 02:15:00 | 450000 | 2 | True |
| 1 | 2026-11-02 11:40:00 | 12000 | 11 | False |
| 2 | 2026-11-03 04:05:00 | 300000 | 4 | True |
| 3 | 2026-11-03 19:20:00 | 8000 | 19 | False |

### 4.2 JSON: чтение справочника

**Что это.** JSON — текстовый формат для объектов и списков. Его используют API, конфиги и справочники. В Python он читается в обычные словари и списки.

| JSON | Python |
|---|---|
| `{"zone_id": "Z01"}` — объект | `dict` — словарь |
| `[ ... ]` — массив | `list` — список |
| `"текст"` | `str` |
| `12`, `3.5` | `int`, `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

**Зачем.** Справочник зон пришёл не таблицей, а списком объектов: `[{zone_id, zone_name, zone_type}, ...]`. Его нужно прочитать, превратить в DataFrame и проверить ключ.

**Код — открыть и прочитать файл:**

```python
with (DATA_DIR / "zones.json").open(encoding="utf-8") as file:
    zone_records = json.load(file)

print(type(zone_records).__name__)
zone_records[0]
```

| Часть | Что делает |
|---|---|
| `(DATA_DIR / "zones.json")` | Путь к файлу (`Path`, см. 1.1) |
| `.open(encoding="utf-8")` | Метод `Path`: открыть файл на чтение. Возвращает **файловый объект** |
| `with ... as file:` | Сохранить файловый объект в переменную `file` на время блока и **закрыть файл автоматически** после блока |
| `    zone_records = json.load(file)` | Тело блока — с отступом 4 пробела. `json.load` — функция модуля `json`: читает JSON из файлового объекта в объекты Python |
| `zone_records[0]` | Первый элемент списка по позиции |

> **Python: `with ... as`.** Конструкция самого Python для ресурсов, которые надо «закрыть» после использования: файлы, соединения с базой.
>
> ```python
> with <что открыть> as <имя>:
>     <работа с ресурсом>     # отступ — это тело блока
> <здесь ресурс уже закрыт>
> ```
>

### 4.3 merge: соединение таблиц по ключу

**Что это.** `merge` соединяет две таблицы по общему ключу, как `JOIN` в SQL. Для каждой строки левой таблицы ищется строка правой с тем же значением ключа, и её столбцы добавляются справа.

**Зачем.** В `trips` только код зоны `Z03`. Название «Вокзал» лежит в другом файле. Соединять по порядку строк нельзя: первая заявка не имеет отношения к первой зоне. Связь — только через ключ `zone_id`.

Отношение **многие к одному**:

```text
trips (168 строк)                  zones (5 строк)
trip_id  zone_id                   zone_id  zone_name
1001     Z01  ───────────────┐
1005     Z01  ───────────────┼──►  Z01      Центр
1009     Z01  ───────────────┘
1002     Z03  ──────────────────►  Z03      Вокзал
1093     Z99  ──────────────────►  (нет пары → NaN)
```

SQL-аналог того, что делаем:

```sql
SELECT t.*, z.zone_name, z.zone_type
FROM trips t
LEFT JOIN zones z ON t.zone_id = z.zone_id;
```

**Код:**

```python
joined = trips.merge(
    zones,
    on="zone_id",
    how="left",
    validate="many_to_one",
    indicator=True,
)
```

| Часть | Что делает |
|---|---|
| `trips.merge(` | Метод DataFrame. `trips` — **левая** таблица |
| `zones,` | **Правая** таблица — первый аргумент |
| `on="zone_id"` | Ключ: столбец с одинаковым именем в обеих таблицах |
| `how="left"` | Сохранить **все** строки левой, даже без пары |
| `validate="many_to_one"` | Проверить, что справа ключ уникален. Если нет — `MergeError` и остановка |
| `indicator=True` | Добавить служебный столбец `_merge`: нашлась ли пара |

Варианты `how`:

| `how=` | Какие строки остаются | SQL |
|---|---|---|
| `"left"` | Все из левой; без пары — `NaN` справа | `LEFT JOIN` |
| `"inner"` (по умолчанию!) | Только с парой в обеих | `INNER JOIN` |
| `"right"` | Все из правой | `RIGHT JOIN` |
| `"outer"` | Все из обеих | `FULL OUTER JOIN` |

Варианты `validate`:

| `validate=` | Что требуется |
|---|---|
| `"one_to_one"` | Ключ уникален в обеих таблицах |
| `"one_to_many"` | Ключ уникален в левой |
| `"many_to_one"` | Ключ уникален в правой (справочник) |
| `"many_to_many"` | Ничего не проверяет |

```python
joined[["trip_id", "zone_id", "zone_name", "status", "_merge"]].head()
```

|   | trip_id | zone_id | zone_name | status | _merge |
|---|---|---|---|---|---|
| 0 | 1001 | Z01 | Центр | cancelled | both |
| 1 | 1002 | Z03 | Вокзал | completed | both |
| 2 | 1003 | Z02 | Университет | completed | both |
| 3 | 1004 | Z03 | Вокзал | completed | both |
| 4 | 1005 | Z01 | Центр | completed | both |

**Код — сколько нашлось пар:**

```python
joined["_merge"].value_counts()
```

```text
_merge
both          167
left_only       1
right_only      0
Name: count, dtype: int64
```

| Значение `_merge` | Смысл |
|---|---|
| `both` | Пара найдена |
| `left_only` | Строка из левой, справа пары нет |
| `right_only` | Строка из правой, слева пары нет (при `how="left"` всегда 0) |

`right_only` выводится с нулём, потому что `_merge` имеет тип `category` — набор возможных значений фиксирован.

**Код — какая заявка без зоны:**

```python
unmatched = joined.loc[
    joined["_merge"] == "left_only",
    ["trip_id", "zone_id", "zone_name", "status", "fare_kzt"],
]
unmatched
```

|   | trip_id | zone_id | zone_name | status | fare_kzt |
|---|---|---|---|---|---|

`Z99` нет в справочнике. Заявку не удаляем (её оплата реальна) и название не выдумываем.

**Код — подпись для отчёта:**

```python
joined["zone_report"] = joined["zone_name"].fillna("Неизвестная зона")
joined.loc[joined["_merge"] == "left_only", ["trip_id", "zone_id", "zone_report"]]
```

|   | trip_id | zone_id | zone_report |

Новый столбец, а не замена `zone_name`: в исходном столбце `NaN` остаётся, и проблема справочника по-прежнему видна.

**Что вернётся.** Новый `DataFrame`: столбцы левой + столбцы правой (ключ один раз) + `_merge`. Индекс — **новый**, 0, 1, 2… (у `trips` он и так был 0–167, поэтому здесь совпал). При `how="left"` и `many_to_one` строк столько же, сколько в левой.

**Типичные ошибки:**

1. Забыть `how=` — по умолчанию `inner`, и строки без пары **молча** пропадут.
2. Разный тип ключа: `11` (число) слева и `"11"` (строка) справа → `ValueError: You are trying to merge on int64 and object columns ...`. Приведите к одному типу через `astype`.
3. Одинаковые неключевые столбцы в обеих таблицах — pandas переименует их в `x_x` и `x_y`. Заранее уберите лишнее или задайте `suffixes=("_trip", "_zone")`.

### 4.4 Проверка объединения: LEFT, INNER и validate

**Что это.** Три обязательные проверки после `merge` + две демонстрации: что теряет `inner` и что ловит `validate`.

**Зачем.** Результат `merge` может выглядеть нормально и быть неверным по числу строк. Типичные поломки: строки пропали (`inner`) или размножились (повтор ключа в справочнике).

**Код — три проверки:**

```python
assert len(joined) == len(trips), "merge изменил число заявок"
assert joined["trip_id"].is_unique, "После merge размножились ID"
assert np.isclose(joined["fare_kzt"].sum(), trips["fare_kzt"].sum())
print("Строки, ключи и сумма сохранены.")
```

| Проверка | Что ловит |
|---|---|
| Число строк до = после | Потерю строк или размножение |
| ID уникален | Размножение конкретных заявок |
| Сумма оплат до = после | Потерю или задвоение денег |

```text
Строки, ключи и сумма сохранены.
```

**Код — LEFT против INNER:**

```python
inner_joined = trips.merge(zones, on="zone_id", how="inner", validate="many_to_one")
print("Заявок в LEFT:", len(joined))
print("Заявок в INNER:", len(inner_joined))
print("Потерянная сумма, ₸:", joined["fare_kzt"].sum() - inner_joined["fare_kzt"].sum())
```

```text
Заявок в LEFT: 168
Заявок в INNER: 167
Потерянная сумма, ₸: 2700.0
```

`inner` молча выкинул заявку 1093 из `Z99` вместе с 2700 ₸. Ошибки нет, таблица выглядит нормально — видно только по числам.

**Код — что ловит validate:**

```python
bad_zones = pd.concat([zones, zones.iloc[[0]]], ignore_index=True)
try:
    trips.merge(bad_zones, on="zone_id", how="left", validate="many_to_one")
except pd.errors.MergeError:
    print("Проверка сработала: в правой таблице один zone_id встречается дважды.")
```

| Часть | Что делает |
|---|---|
| `zones.iloc[[0]]` | Первая строка как `DataFrame` (список в скобках). `iloc[0]` дал бы `Series` |
| `pd.concat([a, b])` | Функция pandas: поставить таблицы друг под другом. Принимает **список** таблиц |
| `ignore_index=True` | Пронумеровать строки заново 0–5, а не повторять старые метки |
| `try:` | Python: попробовать выполнить блок |
| `except pd.errors.MergeError:` | Если в блоке возникла ошибка этого класса — не останавливать программу, а выполнить этот блок |

```text
Проверка сработала: в правой таблице один zone_id встречается дважды.
```

Без `try/except` было бы: `MergeError: Merge keys are not unique in right dataset; not a many-to-one merge`. В ноутбуке ошибка перехвачена, только чтобы `Run All` не останавливался.

**Что было бы без `validate`** (проверено на тех же данных): `Z01` в справочнике дважды → каждая из 30 заявок `Z01` удвоилась. Строк 198 вместо 168, `trip_id` не уникален, сумма оплат 373 150 ₸ вместо 308 400 ₸ — завышена на 64 750 ₸, то есть на все оплаты `Z01`. И никакой ошибки.

**Что вернётся.** Проверки ничего не возвращают либо останавливают код. `pd.concat` → новый `DataFrame`. `merge` с нарушенным `validate` → исключение `MergeError`.

**Типичные ошибки:**

1. Проверять результат `merge` глазами по `head()` — потеря одной строки или задвоение 30 строк там не видны.
2. Использовать `inner` «потому что красивее, без `NaN`» — теряются строки и деньги.
3. Ставить `validate="many_to_many"` или не ставить вовсе, чтобы ошибка «не мешала». Ошибка как раз и говорит, что справочник испорчен.

**Банковский пример.** Продолжение `tx` + `clients` из 4.3.

Проверки для LEFT проходят: 6 строк, `txn_id` уникален, сумма 1 262 300 ₸ сохранена. INNER (`how="inner"`) оставил бы 5 транзакций и потерял 2 300 ₸ клиента 99.

Теперь в справочник по ошибке попала вторая запись клиента 12 с другим сегментом:

```python
bad_clients = pd.concat(
    [clients, pd.DataFrame({"client_id": [12], "name": ["Данияр"], "segment": ["mass"]})],
    ignore_index=True,
)
tx.merge(bad_clients, on="client_id", how="left", validate="many_to_one")
```

```text
MergeError: Merge keys are not unique in right dataset; not a many-to-one merge
```

Без `validate` получится 7 строк вместо 6, сумма 1 782 300 ₸ вместо 1 262 300 ₸, а транзакция 502 на 520 000 ₸ задвоится — один раз как `premium`, второй как `mass`:

|   | txn_id | client_id | amount_kzt | segment |
|---|---|---|---|---|
| 1 | 502 | 12 | 520000 | premium |
| 2 | 502 | 12 | 520000 | mass |

В банковском отчёте это значит завышенный оборот premium-сегмента и mass-сегмента одновременно.

#### Выжимка для конспекта

1. Дата из CSV — строка. `to_datetime` с явным `format` и `errors="raise"`.
2. `.dt` работает только после `to_datetime`: `.dt.hour`, `.dt.date`.
3. JSON → `dict`/`list`. `with ... as f:` закрывает файл сам. `load` — файл, `loads` — строка.
4. Ключ справочника: заполнен и уникален — проверить до `merge`.
5. `merge` = JOIN по ключу, никогда не по порядку строк.
6. По умолчанию `how="inner"` — строки без пары пропадут молча. Для обогащения — `how="left"`.
7. `validate="many_to_one"` — защита от размножения строк. `indicator=True` — видно, кто не нашёл пару.
8. После `merge` три проверки: число строк, уникальность ID, сумма.
9. Без пары — не удаляем и не выдумываем: отдельная подпись «Неизвестная зона», исходный `NaN` остаётся.

#### Где пригодится в AI Engineering

- **JSON** — формат запросов и ответов LLM API, аргументов tool calling и structured output. `json.load`/`json.loads` и проверка ключей — ежедневная работа.
- **RAG:** найденные фрагменты обогащают метаданными из каталога документов по `doc_id` — это `merge` many-to-one. Повтор `doc_id` в каталоге задвоит контекст в промпте, поэтому нужен `validate`.
- **Даты:** фильтр «только актуальные документы» и разбор логов запросов к модели по часам требуют настоящего типа `datetime`, а не строки.

## Часть 5. Отчёт по зонам, сохранение файлов, финальный вывод

Разделы ноутбука 11–13. Работаем с `joined` из части 4: 168 заявок + название зоны + столбец `zone_report`.

Вопросы, на которые отвечает отчёт: сколько заявок в зоне, сколько завершилось, какая доля отмен, сколько оплат, какова типичная длительность.

### 5.1 Флаги и проверка правил данных

**Что это.** Флаг — столбец из `True`/`False`. При суммировании `True` = 1, поэтому `sum` по флагу даёт количество.

**Зачем.** Через флаги в одном `agg` считаются и все заявки, и завершённые, и отменённые — без отдельных фильтров для каждой метрики.

```python
joined["is_completed"] = joined["status"] == "completed"
joined["is_cancelled"] = joined["status"] == "cancelled"
joined[["trip_id", "status", "is_completed", "is_cancelled"]].head()
```

|   | trip_id | status | is_completed | is_cancelled |
|---|---|---|---|---|
| 0 | 1001 | cancelled | False | True |
| 1 | 1002 | completed | True | False |
| 2 | 1003 | completed | True | False |
| 3 | 1004 | completed | True | False |
| 4 | 1005 | completed | True | False |

**Код — проверить правила, на которых держится отчёт:**

```python
assert set(joined["status"].unique()) == {"completed", "cancelled"}
assert joined.loc[joined["is_cancelled"], "fare_kzt"].isna().all()
assert joined.loc[joined["is_completed"], "fare_kzt"].notna().all()
print("Правила учебной схемы подтверждены.")
```

| Строка | Какое правило проверяет |
|---|---|
| 1 | Статусов ровно два. Если появится `refunded`, флаги перестанут покрывать все заявки |
| 2 | У всех отмен оплаты нет |
| 3 | У всех завершённых оплата есть |

```text
Правила учебной схемы подтверждены.
```

> **Python: множество (`set`).** `{"completed", "cancelled"}` — множество: набор **уникальных** значений **без порядка**. Фигурные скобки без пар `ключ: значение` — это `set`, с парами — `dict`.
> - `joined["status"].unique()` — метод pandas: массив уникальных значений, в порядке появления: `['cancelled' 'completed']`.
> - `set(...)` — встроенная функция Python: превратить в множество.
>
> Зачем `set`: массив `['cancelled', 'completed']` и список `['completed', 'cancelled']` не равны из-за порядка, а два множества с одинаковыми элементами равны всегда.

Почему правила 2–3 важны: `sum` в следующем шаге **пропускает** `NaN`. Сумма оплат правильная, только если пустые значения — именно отмены. В реальном сервисе с платными отменами и возвратами правило расчёта будет другим.

**Типичные ошибки:** сравнивать `unique()` со списком (`== ["completed", "cancelled"]`) — сравнение идёт поэлементно, результат — массив `True`/`False`, и `assert` упадёт с `ValueError: The truth value of an array ... is ambiguous`; считать по флагам, не проверив, что статусов только два; переносить «`sum` пропускает `NaN` — и хорошо» на другие данные без проверки.

### 5.2 Сводный отчёт по зонам

**Что это.** Одна таблица: строка — зона, столбцы — все метрики отчёта с явными знаменателями.

**Код:**

```python
zone_report = joined.groupby("zone_report", as_index=False).agg(
    requests=("trip_id", "size"),
    completed_trips=("is_completed", "sum"),
    cancelled_requests=("is_cancelled", "sum"),

    known_duration=("duration_min", "count"),
    median_duration_min=("duration_min", "median"),
)
```

| Строка | Что считает |
|---|---|
| `as_index=False` | Зона остаётся **обычным столбцом**, а индекс — 0, 1, 2… Удобно для сохранения в файл |
| `requests` | Все заявки зоны |
| `completed_trips` | Сумма флага = число завершённых |
| `cancelled_requests` | Сумма флага = число отмен |
| `payments_kzt` | Сумма известных оплат (отмены пропускаются как `NaN`) |
| `known_duration` | Сколько длительностей известно |
| `median_duration_min` | Медиана только по известным длительностям |

```python
zone_report["cancel_pct"] = zone_report["cancelled_requests"] / zone_report["requests"] * 100
zone_report.round(1)
```

**Типичные ошибки:**

1. Без `as_index=False` зона уйдёт в индекс, а `to_csv(index=False)` её **выбросит** — в файле останутся числа без названий зон (проверено ниже, в банковском примере).

### 5.4 Сохранение в CSV и JSON

**Что это.** `to_csv` и `to_json` — методы DataFrame, которые записывают таблицу в файл.

**Зачем.** Отчёт полезен, когда его может открыть другой человек: CSV — в Excel, JSON — в другой программе или через API. Сохраняем в отдельную папку `output/`, исходные файлы не перезаписываем.

**Код:**

```python
report_to_save = zone_report.round({"median_duration_min": 1, "cancel_pct": 1})
csv_path = OUTPUT_DIR / "zone_report.csv"
json_path = OUTPUT_DIR / "zone_report.json"
report_to_save.to_csv(csv_path, index=False, encoding="utf-8-sig")
report_to_save.to_json(json_path, orient="records", force_ascii=False, indent=2)
print("Сохранены:", csv_path.name, "и", json_path.name)
```

| Часть | Что делает |
|---|---|
| `round({"столбец": 1, ...})` | Словарь: округлить **только** указанные столбцы, каждый до своего числа знаков. `zone_report` не меняется — округлённая копия только для файла |
| `OUTPUT_DIR / "zone_report.csv"` | Путь к будущему файлу (`Path`, см. 1.1) |
| `index=False` | Не записывать индекс отдельным столбцом. Иначе в файле появится безымянный столбец `2, 0, 4…` |
| `encoding="utf-8-sig"` | UTF-8 с меткой BOM в начале файла. По ней Excel понимает, что это UTF-8, и показывает кириллицу правильно |
| `orient="records"` | Форма JSON: список объектов, один объект = одна строка таблицы |
| `force_ascii=False` | Писать кириллицу как есть. Иначе «Центр» запишется как `\u0426\u0435\u043d\u0442\u0440` |
| `indent=2` | Отступы для читаемости человеком |

```text

```

Как выглядят файлы (тот же код, перезапущенный отдельно, размеры совпали с ноутбуком: 414 и 1384 байт).

### 5.5 Round-trip: прочитать обратно и сравнить

**Что это.** Round-trip: записали → прочитали → убедились, что смысл не потерялся.

**Зачем.** Файл мог записаться не так, как вы думаете: потерять столбец, исказить кодировку, изменить числа. Проверка чтением — единственный способ узнать.

**Код — прочитать:**

```python
csv_back = pd.read_csv(csv_path)
json_back = pd.read_json(json_path, orient="records")
display(csv_back.head(3))
display(json_back.head(3))
```

`csv_back`:

|   | zone_report | requests | completed_trips | cancelled_requests | payments_kzt | known_duration | median_duration_min | cancel_pct |
|---|---|---|---|---|---|---|---|---|
| 0 | Жилой район | 46 | 39 | 7 | 84800.0 | 38 | 28.8 | 15.2 |
| 1 | Вокзал | 36 | 30 | 6 | 63700.0 | 29 | 28.8 | 16.7 |
| 2 | Университет | 33 | 27 | 6 | 60900.0 | 27 | 30.7 | 18.2 |

`json_back`:

|   | zone_report | requests | completed_trips | cancelled_requests | payments_kzt | known_duration | median_duration_min | cancel_pct |
|---|---|---|---|---|---|---|---|---|
| 0 | Жилой район | 46 | 39 | 7 | 84800 | 38 | 28.8 | 15.2 |
| 1 | Вокзал | 36 | 30 | 6 | 63700 | 29 | 28.8 | 16.7 |
| 2 | Университет | 33 | 27 | 6 | 60900 | 27 | 30.7 | 18.2 |

Разница: в JSON `payments_kzt` прочитался как целое (`84800` вместо `84800.0`). Значение то же, тип другой.

**Код — сравнить:**

```python
expected = report_to_save.reset_index(drop=True)
pd.testing.assert_frame_equal(expected, csv_back, check_dtype=False, atol=1e-8, rtol=1e-8)
pd.testing.assert_frame_equal(expected, json_back, check_dtype=False, atol=1e-8, rtol=1e-8)
print("CSV и JSON прочитаны без потерь значений.")
```

| Часть | Что делает |
|---|---|
| `reset_index(drop=True)` | Новый индекс 0, 1, 2…, старый **выбросить** (`drop=True`), а не превращать в столбец. Нужно, потому что у `report_to_save` индекс `2, 0, 4…`, а у прочитанных файлов — `0, 1, 2…` |
| `pd.testing.assert_frame_equal(a, b)` | Функция pandas для проверок: таблицы равны по столбцам, индексу и значениям. Если нет — `AssertionError` с описанием различия |
| `check_dtype=False` | Не сравнивать типы: `84800.0` и `84800` считаются равными |
| `atol=1e-8, rtol=1e-8` | Допуск для дробных чисел, как у `np.isclose`. `1e-8` — запись числа 0.00000001 |

```text
CSV и JSON прочитаны без потерь значений.
```

Без `reset_index` проверка падает сразу: `DataFrame.index values are different (100.0 %)`.

**Код — что лежит в папке:**

```python
print("Результаты:", RUN_DIR.name + "/output/")
for file in OUTPUT_DIR.iterdir():
    print("-", file.name, "|", file.stat().st_size, "байт")
```

```text

- zone_report.json | 1384 байт
- zone_report.csv | 414 байт
```

> **Python: цикл `for`.** `for file in коллекция:` — повторить тело (строки с отступом) для каждого элемента, по очереди кладя его в переменную `file`.
> - `OUTPUT_DIR.iterdir()` — метод `Path`: перебрать всё содержимое папки. Каждый элемент — тоже `Path`.
> - `file.stat()` — метод: сведения о файле; `.st_size` — атрибут с размером в байтах.
> - `RUN_DIR.name + "/output/"` — `+` для строк склеивает текст.
>
> Здесь цикл уместен: файлов два, и это работа с диском, а не вычисления по строкам таблицы. Для столбцов pandas цикл не нужен (см. 2.5).

**Типичные ошибки:**

1. Сравнивать без `reset_index(drop=True)` — падение из-за индекса, хотя данные одинаковые.
2. `reset_index()` без `drop=True` — старый индекс станет лишним столбцом `index`, и таблицы опять не совпадут.
3. Требовать точного совпадения типов после CSV/JSON — форматы не хранят типы pandas; сравниваем значения.

**Банковский пример.** Сохранение отчёта по сегментам из 5.2 и проверка:

```python
seg.to_json(p, orient="records", force_ascii=False, indent=2)
back = pd.read_json(p, orient="records")
pd.testing.assert_frame_equal(seg, back, check_dtype=False)
```

```json
    "segment":"mass",
    "txn_count":5,
    "declined":2,
    "decline_pct":40.0
  },
```

### 5.6 Финальный вывод и f-строки

**Что это.** Короткий текстовый вывод: пять предложений с числами и ограничениями вместо «всё посчиталось».

**Зачем.** Читатель отчёта не будет запускать код. Ему нужны ответ, знаменатель и честное «чего мы не знаем».

**Код — опорные числа:**

```python
total_requests = len(trips)
completed_count = int((trips["status"] == "completed").sum())
cancelled_count = int((trips["status"] == "cancelled").sum())
total_payments = completed["fare_kzt"].sum()
```

- `int(...)` — встроенная функция Python: привести к обычному целому. `sum()` маски возвращает тип NumPy `int64`; `int` делает из него привычное число Python — например, для JSON или красивой печати.

```python
print("Уникальных заявок:", total_requests)
print("Завершено:", completed_count, "| Отменено:", cancelled_count)
print("Доля отмен, %:", round(cancelled_count / total_requests * 100, 1))
print("Сумма оплат, ₸:", total_payments)
print("Заявок без зоны в справочнике:", len(unmatched))
```

`round(число, 1)` — встроенная функция Python: округлить до 1 знака (у pandas — метод `.round(1)`, у чисел Python — функция).

```text
Уникальных заявок: 168
Завершено: 139 | Отменено: 29
Доля отмен, %: 17.3
Сумма оплат, ₸: 308400.0
Заявок без зоны в справочнике: 1
```

**Вывод по шаблону ноутбука, с числами из всех частей:**

1. В исходной выгрузке 170 строк; после удаления 2 полных повторов осталось 168 уникальных заявок.
2. Завершено 139 заявок, отменено 29; доля отмен среди всех заявок равна 17.3%.
3. Самая большая группа по числу заявок — Жилой район: 46 заявок. Это описание этой выгрузки.
4. У 2 завершённых поездок неизвестна длительность, поэтому сводка длительности описывает 137 измерений.
5. У 1 заявки не нашлось зоны. LEFT JOIN сохранил её и сумму оплаты. Все данные синтетические, поэтому переносить выводы на реальный город нельзя.

**f-строки: как собрать такое предложение кодом.** В основной части ноутбука f-строк нет, но для выводов они удобнее, чем `print` через запятые.

```python
print(f"Завершено {completed_count} заявок, отменено {cancelled_count}; доля отмен — {cancelled_count / total_requests:.1%}.")
print(f"Сумма оплат: {total_payments:,.0f} ₸")
```

```text
Завершено 139 заявок, отменено 29; доля отмен — 17.3%.
Сумма оплат: 308,400 ₸
```

> **Python: f-строка.** Буква `f` перед кавычками — это синтаксис самого Python (с версии 3.6). Внутри `{...}` можно написать любое выражение — переменную, арифметику, вызов функции; Python вычислит его и вставит результат в текст.
>
> После двоеточия внутри скобок — **формат**:
>
> | Запись | Что делает | Пример результата |
> |---|---|---|
> | `{x}` | Вставить как есть | `139` |
> | `{x:.1f}` | 1 знак после точки | `17.3` |
> | `{x:.1%}` | Умножить на 100, 1 знак, знак `%` | `17.3%` из `0.1726` |
> | `{x:,.0f}` | Разделитель тысяч, без дробной части | `308,400` |
>
> Без `f` фигурные скобки останутся в тексте буквально: `"{completed_count}"` так и напечатается.

**Типичные ошибки:**

1. Забыть `f` перед кавычками — в выводе будет `{cancelled_count}` вместо числа.
2. `{x:.1%}` для уже умноженного на 100 числа → `1730.0%`. `%`-формат сам умножает на 100.
3. Вывод без ограничений: «Жилой район — самая востребованная зона города». Правильно: «в этой синтетической выгрузке больше всего заявок из Жилого района».

#### Выжимка для конспекта

1. Флаг = маска в столбце; `sum` по флагу = количество.
2. Перед отчётом проверяем правила данных (`set` статусов, оплата у отмен пустая).
3. `as_index=False` — ключ остаётся столбцом, иначе потеряется в CSV.
4. Доля — от заявок своей группы; рядом всегда число заявок.
5. Сохраняем в отдельную папку, исходники не трогаем. CSV: `index=False`, `utf-8-sig`. JSON: `records`, `force_ascii=False`.
6. Round-trip: записали → прочитали → `assert_frame_equal` с `reset_index(drop=True)` и `check_dtype=False`.
7. f-строка: `f"... {выражение:формат} ..."`; `:.1%` сам умножает на 100.
8. Вывод = числа + знаменатели + ограничения. Описываем выгрузку, а не город.

#### Где пригодится в AI Engineering

- **Отчёты по evaluation:** результаты прогона модели собирают в такую же таблицу (метрика + число примеров по срезам) и сохраняют в JSON/CSV, чтобы сравнивать версии промптов и моделей между запусками.
- **`orient="records"`** — та же форма, что у JSON-ответов API и JSONL-датасетов для fine-tuning и eval: список объектов, один объект — один пример.
- **Round-trip-проверки** нужны при выгрузке датасетов и логов: потерянная кодировка или столбец незаметно испортят eval-набор.

## Часть 6. Бонус: pivot_table и заявки по часам

Раздел ноутбука 16, необязательный. Используются `joined` (часть 4–5) и столбец `request_hour` (4.1).

### 6.1 pivot_table: сводка по двум категориям

**Что это.** `pivot_table` строит таблицу «категория × категория»: одна категория по строкам, другая по столбцам, в ячейках — показатель. Как сводная таблица в Excel.

**Зачем.** В 5.2 отмены и завершения считались через два флага. `pivot_table` показывает то же сразу для всех значений `status` — и если появится третий статус, он станет новым столбцом сам.

```python
status_pivot = joined.pivot_table(
    index="zone_report", columns="status", values="trip_id",
    aggfunc="size", fill_value=0,
)
status_pivot
```

| Аргумент | Что задаёт |
|---|---|
| `index="zone_report"` | Что по строкам |
| `columns="status"` | Что по столбцам: каждое значение статуса — отдельный столбец |
| `values="trip_id"` | По какому столбцу считать |
| `aggfunc="size"` | Какую функцию применить — число строк. **По умолчанию `"mean"`** |
| `fill_value=0` | Чем заполнить комбинацию, которой нет в данных |

| status | cancelled | completed |
|---|---|---|
| **zone_report** | | |
| Вокзал | 6 | 30 |
| Деловой район | 6 | 16 |
| Жилой район | 7 | 39 |
| Неизвестная зона | 0 | 1 |
| Университет | 6 | 27 |
| Центр | 4 | 26 |

Числа совпадают с `completed_trips` и `cancelled_requests` из 5.2 — это хорошая перекрёстная проверка.

**Когда 0 — честно, а когда нет.** У «Неизвестной зоны» нет отмен в этой выгрузке — значит, количество действительно 0. Это верно только для **количества** в фиксированной выгрузке. Для длительности или суммы пустая ячейка значит «нет данных», и `fill_value=0` исказил бы среднее.

**Что вернётся.** `DataFrame`: индекс — значения `index`, столбцы — значения `columns`; над столбцами — их имя (`status`).

Похожие инструменты:

| Запись | Когда удобнее |
|---|---|
| `df.pivot_table(index=, columns=, values=, aggfunc=)` | Любой показатель по двум категориям |
| `pd.crosstab(df["a"], df["b"])` | Только количество — короче, без `values` и `aggfunc`. Здесь дал бы ту же таблицу |
| `df.groupby(["a", "b"]).size()` | Тот же результат «длинной» `Series`, без разворота в столбцы |

**Типичные ошибки:**

1. Забыть `aggfunc`. Получится **среднее `trip_id`** — например, `1096.67` для отмен на Вокзале. Ошибки нет, таблица выглядит «числовой», но смысла ноль.
2. Без `fill_value=0` у отсутствующей комбинации будет `NaN`, а все числа станут дробными (`6.0`, `30.0`).
3. `fill_value=0` для средних и сумм там, где «нет данных», а не «ноль событий».

**Банковский пример.** Число транзакций по сегменту и типу операции:

```python
tx = pd.DataFrame({
    "txn_id":   [501, 502, 503, 504, 505, 506, 507, 508],
    "segment":  ["mass", "premium", "mass", "mass", "premium", "mass", "mass", "premium"],
    "txn_type": ["card", "transfer", "atm", "card", "card", "transfer", "card", "card"],
    "op_hour":  [2, 11, 14, 9, 23, 16, 10, 13],
})
tx.pivot_table(index="segment", columns="txn_type", values="txn_id",
               aggfunc="size", fill_value=0)
```

| txn_type | atm | card | transfer |
|---|---|---|---|
| **segment** | | | |
| mass | 1 | 3 | 1 |
| premium | 0 | 2 | 1 |

Premium-клиенты в этой выборке не снимают наличные — 0 здесь честный: операций такого типа нет.

```python
requests_by_hour = trips.groupby("request_hour").size()
```

### 6.3 Мини-проект: до и после полудня, np.where

**Задача из ноутбука.** Сравнить заявки до 12:00 и с 12:00: размер групп, число и доля отмен, проверка, что заявки не потерялись. Вывод — без выдуманных причин.

Решение ниже взято из ноутбука («для самопроверки»). Если хотите сначала попробовать сами — остановитесь здесь.

```python
bonus = joined.copy()
bonus["period"] = np.where(bonus["request_hour"] < 12, "До 12:00", "С 12:00")
bonus_report = bonus.groupby("period").agg(
    requests=("trip_id", "size"), cancellations=("is_cancelled", "sum")
)
```

| Часть | Что делает |
|---|---|
| `bonus = joined.copy()` | Учебный признак — на копии, `joined` не трогаем |
| `np.where(условие, a, b)` | Функция NumPy: для каждой строки взять `a`, где условие `True`, и `b`, где `False` |
| `bonus["request_hour"] < 12` | Маска: заявка до полудня |
| `groupby("period").agg(...)` | Две группы: число заявок и сумма флага отмен (флаг из 5.1) |

> **NumPy: `np.where`.** Векторная версия «если — то — иначе» для целого столбца: `np.where(маска, значение_если_да, значение_если_нет)`. Возвращает массив NumPy той же длины, pandas принимает его как новый столбец. Цикл и `if` по строкам не нужны.

```python
bonus_report["cancel_pct"] = bonus_report["cancellations"] / bonus_report["requests"] * 100
assert bonus_report["requests"].sum() == len(trips)
bonus_report.round(1)
```

|   | requests | cancellations | cancel_pct |
|---|---|---|---|
| **period** | | | |
| До 12:00 | 84 | 18 | 21.4 |
| С 12:00 | 84 | 11 | 13.1 |

Как сформулировать вывод без выдуманных причин: «В этой синтетической выгрузке группы равны — по 84 заявки. До полудня отменено 18 из 84 (21.4%), после — 11 из 84 (13.1%); данные не объясняют, почему так». Нельзя: «утром водителей не хватает» — таких данных в таблице нет.

**Типичные ошибки:**

1. `np.where` и пропуски: сравнение с `NaN` даёт `False`, поэтому строка с неизвестным часом **молча** попадёт во вторую группу. Проверено: `np.where(pd.Series([8.0, np.nan, 13.0]) < 12, "До", "После")` → `['До' 'После' 'После']`. Здесь пропусков в `request_hour` нет, но в реальных данных сначала проверьте `isna().sum()`.
2. Граница: `< 12` относит 12:00 ко второй группе. Подписи групп должны совпадать с условием («До 12:00» / «С 12:00»).
3. Сравнивать проценты без размера групп. Здесь группы равны, но так бывает редко.

**Банковский пример.** Операции в рабочее время и вне его (`tx` из 6.1):

```python
tx["period"] = np.where(tx["op_hour"].between(9, 18), "Рабочее время", "Вне рабочего времени")
tx.groupby("period").size()
```

```text
period
Вне рабочего времени    2
Рабочее время           6
dtype: int64
```

Такой признак часто идёт в антифрод-правила: операции в 02:00 и 23:00 проверяют строже.

#### Шпаргалка

| Запись | Что делает |
|---|---|
| `df.pivot_table(index="a", columns="b", values="id", aggfunc="size", fill_value=0)` | Число строк по комбинациям `a` × `b` |
| `aggfunc=` | Обязательно указать: по умолчанию `"mean"` |
| `fill_value=0` | Пустые комбинации → 0 (только для количеств) |

| `ax.set_xticks(s.index)` | Подпись на каждом значении оси X |

#### Выжимка для конспекта

1. `pivot_table` = сводка «строки × столбцы»; всегда явный `aggfunc`.

3. Сверяй `pivot_table` с уже посчитанными флагами — перекрёстная проверка.
4. Час «все дни вместе» ≠ конкретный день.
5. Линия — для упорядоченной оси (время), столбцы — для категорий. Ось Y — от нуля.
6. Ровный график здесь — свойство синтетики, не вывод о городе.
7. `np.where(маска, a, b)` — новый признак без цикла; `NaN` в условии уходит в ветку «нет».
8. Вывод: размер групп + знаменатель доли + никаких выдуманных причин.
